# zkpp

The server side of StructuredID's Zero-Knowledge Password Policy (ZKPP): a
zero-knowledge proof that a password meets the server's policy and was not
used on the account before, without revealing the password. The proof is
bound to the password operation and to the OPAQUE (RFC 9807) registration
request it goes with, so it is no proof for another password, operation or
registration.

The crate `sid-pake-core` contains:

- the circuit (Halo2 on the Pasta curves, `k = 11`): policy engine, OPAQUE
  binder (the OPAQUE element `M = blind·H(P)` of the checked password), breach
  Bloom non-membership and the history tags;
- the verifier, which refuses malformed proofs by length and encoding before
  the SNARK check;
- a reference prover;
- the private password-history relation (VOPRF with a DLEQ proof) and the
  history checker's tag finalization;
- OPAQUE on Pallas (`PallasCipherSuite` for `sid-opaque-ke`);
- key generation (parameters, verifying and proving keys) per policy and
  history-domain count.

It builds on `halo2_proofs` 0.4.0 as published on crates.io, with no fork.

[docs/construction.md](docs/construction.md) states the relation, its
encodings, the checks outside the proof and what the relation does not
establish, for independent review.

## Clients

Browsers prove with the TypeScript client
[`@structured-id/opaque`](https://github.com/structured-id/opaque), which
implements the same circuit; its test vectors are generated by this crate's
examples.
